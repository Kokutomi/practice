## 2. PDF の入手

PDF の所在：ユーザーの PC の `C:\Users\kooku\actuary\WBnamachu_.pdf`（約44MB、1218ページ）。
Google ドライブにも同じファイル（`WBnamachu_.pdf`、ID `1F7t_s8RSDBEBbtYB_oSL0JZpkAWEo3B2`）がありますが、
ドライブ連携のダウンロード上限は **10MB** のため、そのままでは取得できません。

次のいずれかの方法で受け取ってください（上から順に優先）。

1. **このセッションから PC のフォルダ「actuary」が使える場合**（Remote Control。`list_computer_folders` で使用可能になっているか確認）：直接読む。
2. **チャットへの添付**（1ファイル30MBまで）：ユーザーに、Brave または Edge で開いて Ctrl+P →「PDF に保存」→ページ「カスタム」で
   `1-610` と `611-1218` の2つに分けて添付してもらう（30MB を超える場合は `1-406` / `407-812` / `813-1218`）。
3. **Google ドライブ経由**（1ファイル10MBまで）：ページ範囲 `1-204` / `205-408` / `409-612` / `613-816` / `817-1020` / `1021-1218` の6つに分けてマイドライブに入れてもらい、`download_file_content` で取得する。

分割されたものは `tools/split_pdf.py --join` で1冊に戻し、`data/sources/WBnamachu_.pdf` に置いてください。

```bash
python tools/split_pdf.py data/sources/WBnamachu_.pdf --join "path/to/parts/*.pdf"
```

- 「ブラウザで PDF に保存」で分けた場合、ファイル名に `_partNN_` が含まれないので、`--join` の順序指定に合わせて名前を付け直すか、ページ範囲の順に結合してください。
- **結合後のページ数が1218であること**、`workbook.render()` で p.1・p.11・p.1145 が正しく表示されることを確認してください（§3.1 の索引と一致するか）。

## 4. 作業内容

### 4.1 ワークブックの問題索引（コミット可）
- 全ページの画像を見て、各問題の **問題番号**（例：`11.12`）、**問題ページ**（奇数）、**解答ページ**（偶数）、**節キー**（`workbook.SECTIONS` のキー）、**分野**（`TOPICS` のいずれか）、**自作の一行要約**（30字以内、引用不可）を作ります。
- 1ページに複数問題がある場合・1問が複数ページにまたがる場合も正しく扱ってください。
- 保存先：`problems/workbook_index.json`（コミット可）。形式例：
  ```json
  [{"wb_id": "11.12", "page": 601, "solution_page": 602, "section": "11.2",
    "topic": "加入年齢方式・標準保険料", "summary": "定額制の加入年齢方式で標準保険料を求める",
    "status": "ok"}]
  ```
  読み取りに自信がないものは `"status": "needs_review"` とし、理由を `"note"` に書いてください。
- 進め方：**まず第1章（p.1–10）と第11.2節（p.579–628）だけを作り、ユーザーに確認してもらってから全体に進めてください。** 問題番号の振り方（章内の通し番号か、ページ内番号か）をユーザーと合意してから進めます。

### 4.2 ユーザーの ◎/△ 記録（コミット不可・個人データ）
- 各問題の解答ページから、**すべての「月/日 記号」を漏れなく**読み取ります。記号は ◎・○・△・× を区別してください。
- 保存先：`data/wb_marks.json`（git 管理外）。形式例：
  ```json
  [{"wb_id": "1.1", "page": 2, "month": 10, "day": 22, "mark": "◎", "status": "ok"}]
  ```
- **年は推測で付けないこと。** 月の並び（10〜12月と3月など）から学習期間を推定できる場合も、ユーザーに「どの年の何月から何月に解いたか」を確認してから `year` を付けてください。「最新の評価」の判定は年が確定してから行います。
- アプリへの取り込み：
  - SQLite に `wb_marks` テーブルを追加（`db.SCHEMA`）。
  - `backup.USER_TABLES` に `wb_marks` を追加し、バックアップ JSON で PC 版とスマホ版の間を移せるようにする。
  - `data/wb_marks.json` があれば起動時に自動で取り込む処理を `db.sync_data()` と同様に追加（内容ハッシュで変更検知）。
- 読み取りの検証：最初の50件程度をユーザーに見せて確認してもらい、誤読の傾向を直してから全体に進めてください。

### 4.3 過去問324解答欄 → ワークブックの対応（コミット可）
- 各解答欄（`problems/iaj-*.json` の `id`）について、出題内容が近いワークブックの問題を **1〜3問** 選びます。
- 判断材料：過去問の公式PDF（`params` ではなく、`page` に示された日本アクチュアリー会の問題PDF。URL は `sources/ledger.json`）と、ワークブックの問題ページの画像。**分野名だけでの機械的な対応づけは不可。** 計算の型・使う公式・論点が一致するかで判断してください。
- 保存先：`problems/workbook_map.json`（コミット可）。形式例：
  ```json
  {"IAJ-2025-1-1": [{"wb_id": "1.3", "match": "strong", "reason": "動態的昇給率と静態的昇給率の関係からベースアップ率を求める同型問題"}]}
  ```
  `match` は `strong`（同型）/ `related`（同じ論点）/ `none`（該当なし）。`reason` は自分の言葉で30字程度。
- 完答グループ（`group_key`）や同じ大問の小問は、まとめて判断してかまいません。

### 4.4 アプリへの反映
1. **演習画面**（`app.py`）：出題中の解答欄に対応するワークブックの問題を表示します。
   - 問題番号・要約・対応の強さ・**ユーザーの ◎/△ 履歴**を表示する。
   - PDF がある環境では、その問題ページと手書き解答ページを表示（既存ビューアを、分野単位から問題単位に切り替え）。
   - PDF がない環境（スマホ版）でも、問題番号とページ番号は表示する。
2. **得意・不得意の統合指標**（`dashboard.py`）：分野・節ごとに、次を並べて表示します。
   - アプリでの正答率と確信度
   - ワークブックの ◎/△ 比率と直近の評価
   - 両者を合わせた「弱点度」（定義を README に明記し、テストで固定）
3. **今日のおすすめ**（`recommend.py`）：「ワークブックで△が残っている問題に対応する過去問」「過去問で誤答した論点のワークブック問題」を理由付きで提案します。
4. **学習計画**（`plan.py`）：平日の演習の割り振りに、ワークブックの弱点度を反映します。
5. **Obsidian 書き出し**（`notes.py`）：各過去問ノートに、対応するワークブック問題へのリンク `[[WBnamachu_.pdf#page=N|問題11.12]]` と ◎/△ 履歴を追加します。

### 4.5 テストと確認
- 追加・変更した機能ごとに pytest を追加します（PDF がなくても通るように。PDF 依存のテストは `skipif`）。
- `problems/workbook_index.json` と `problems/workbook_map.json` の整合性テスト：
  - 全 `wb_id` が一意
  - ページが奇数/偶数の規則どおり
  - `section` が `workbook.SECTIONS` に存在する
  - `topic` が `TOPICS` に含まれる
  - map の全キーが `problems/iaj-*.json` の `id` に存在する
  - 参照先の `wb_id` が index に存在する
- `python -m pytest -q` が全件通ること。GitHub Actions も通ること。
- Streamlit の画面を実際に起動し、スクリーンショットで確認すること（PC 幅とスマホ幅）。
- **PDF がない状態**（Streamlit Cloud 相当）で起動し、エラーにならないことを確認すること。
